# Stream Deck MK.2 HID protocol

- **Date:** 2026-10-25
- **Device:** Stream Deck MK.2, model string `20GBA9901`, firmware 1.02.000
- **Host:** Windows 10 Pro 22H2 (build 19045)
- **Method:** `cargo run -p deckly-device --example probe` (enumeration and
  feature-report reads through the Win32 HID API via `async-hid`), with the
  official app running alongside.
- **Tests:** `crates/deckly-device/src/protocol.rs` (`parses_mk2_feature_reports`
  and the encoding tests)

## Observed

- One HID interface: vendor `0x0FD9`, product `0x0080`, usage page `0x000C`,
  usage `0x0001`. The OS reports the product string "Stream Deck MK.2" and the
  serial number.
- The interface can be opened for reading and feature reports while the
  official app is running, so the device is not held exclusively.
- Feature reports are 32 bytes, report id first:
  - `0x05` and `0x07`: `[id, 0x0C, 4 bytes, "1.02.000"]`. The length byte
    counts the 4 bytes plus the 8 ASCII characters.
  - `0x04`: same layout, `"1.00.003"`.
  - `0x06`: `[id, 0x0E, 14 ASCII characters]`, the same serial number the OS
    reports.
  - `0x08`: `03 05 48 00 48 00 E0 01 10 01 04 05 01 04 04`.
  - `0x09`: `01 00 01 00 F3 3A`; `0x0A`: `04`; `0x0B`: `02 40 04`.
  - `0x03`: all zeros.

## Inferred

- `0x05` is the main firmware version (the value matches what we expect for
  this unit); the meaning of `0x04` (second version string) and the 4 bytes in
  front of each version string is not known.
- `0x08` describes the key grid: 3 rows, 5 columns, 72 × 72 px keys
  (little-endian 16-bit), then 480 × 272 px, which matches the full panel
  size. The trailing bytes are unknown. If this holds for other models, Deckly
  can read the layout from the device instead of a table.

## Verified on hardware

Second session, same day, official app closed, Deckly debug build run with
`DECKLY_DEBUG=1` and a numbered test profile (titles 1–15 in row-major order,
two pages, brightness up/down keys). Checked by the owner looking at the
device, and by the event log.

- Key input: input report `0x01`, byte 1 = `0x00` for key events, one byte
  per key from offset 4, non-zero = pressed. The log showed press and release
  of index 1 when the second key of the top row was pressed.
- Key images: output report `0x02` of 1024 bytes, header
  `[0x02, 0x07, key, last-chunk flag, length LE16, chunk index LE16]`, then up
  to 1016 bytes of a 72 × 72 JPEG. Images sent pre-rotated by 180° appear
  upright, and key index `n` is row `n / 5`, column `n % 5` from the top left.
- Brightness: feature report `[0x03, 0x08, percent]` changes the brightness.
- Reset: feature report `[0x03, 0x02]` brings back the device's own logo.

The starting hypothesis for these four items came from widely published
descriptions of this device family; the results above are our own
observations.
